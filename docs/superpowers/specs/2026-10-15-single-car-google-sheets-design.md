# Xswift: แอปข้อมูลรถยนต์คันเดียว

## เป้าหมาย

ปรับ Xswift ให้เป็นแอปสำหรับจัดการข้อมูลรถยนต์เพียงคันเดียว เปิดหน้า “รถยนต์ของฉัน” เป็นหน้าหลักโดยตรง และใช้ Google Sheets ที่ผู้ใช้ระบุเป็นแหล่งข้อมูลหลัก ให้ผู้ใช้ลงชื่อเข้าใช้ Google เพื่ออ่านและบันทึกข้อมูล แล้วเก็บ source ในรีโป Xswift สำหรับโฮสต์หน้าเว็บด้วย GitHub Pages

## ขอบเขต

- นำหน้า ภาพรวม, กำหนดการจ่าย, รหัสผ่าน, เตือนความจำ และ เพิ่มเติม ออกจาก UI และนำการเรียกใช้โค้ดที่รองรับข้อมูลเหล่านั้นออก
- ย้ายหน้ารถยนต์ขึ้นเป็นหน้าแรก โดยคงข้อมูลรุ่นรถ, ทะเบียน, ราคา, วันต่อภาษี, วันสิ้นสุดภาษี, ประเภทและปีประกัน, วันสิ้นสุดประกัน, วันหมดอายุใบขับขี่, บันทึก และรูปภาพรถ/ใบขับขี่
- ใช้ Google Identity Services สำหรับ OAuth และ Google Sheets API สำหรับอ่าน/เขียนข้อมูล การเข้าถึงต้องอยู่ภายใต้บัญชี Google ที่ลงชื่อเข้าใช้ ไม่มีการฝัง service-account secret หรือ credential ลับใน source ที่เผยแพร่
- ใช้ Google Drive API เพื่อจัดเก็บไฟล์รูปให้ใช้ร่วมกันข้ามอุปกรณ์ แล้วเก็บ file ID ในชีต
- ใช้ spreadsheet ID `1xxaLYpoQvzXhIzkHllMToVo-SKeM4TKNik7kqDbKID4` จากลิงก์ที่ผู้ใช้ให้ รักษาแท็บเดิมทั้งหมด และใช้แท็บเฉพาะชื่อ `รถยนต์` สำหรับแอป
- เก็บ source และไฟล์ตั้งค่า/คู่มือในรีโป GitHub `xserdevper-lab/Xswift` และเตรียมโฮสต์ผ่าน GitHub Pages

## โครงสร้างข้อมูล

แท็บ `รถยนต์` เก็บรถเพียงหนึ่งรายการ มีคอลัมน์ `key` และ `value` โดยมี key คงที่ดังนี้: `model`, `plate`, `price`, `taxRenew`, `taxExpire`, `insType`, `insYear`, `insExpire`, `licenseExpire`, `memo`, `carImageFileId`, `licenseImageFileId` การบันทึกต้องอัปเดตค่าตาม key แทนการเพิ่มแถวซ้ำทุกครั้ง หากแท็บไม่มีอยู่ ให้แสดงคำแนะนำการตั้งค่าที่ชัดเจนหรือสร้างแท็บด้วย Sheets API หลังได้รับสิทธิ์ OAuth แล้ว โดยต้องไม่เปลี่ยนแปลงแท็บอื่น

รูปภาพรถและใบขับขี่จัดเก็บเป็นไฟล์ใน Drive ภายใต้สิทธิ์บัญชีผู้ใช้ ใช้ scope `drive.file` และบันทึก file ID กลับในชีต ก่อนเปลี่ยนรูปให้ลบ/แทนที่ไฟล์เดิมที่แอปเป็นเจ้าของ หากทำได้อย่างปลอดภัย

## การยืนยันตัวตนและการซิงก์

- หน้าเว็บแสดงสถานะยังไม่เชื่อมต่อ และปุ่มลงชื่อเข้าใช้เมื่อไม่มี OAuth session
- OAuth Client ID และ spreadsheet ID เป็นค่าตั้งค่าที่เปิดเผยได้และต้องระบุผ่านไฟล์ตั้งค่าตัวอย่าง/ขั้นตอน deployment; ห้าม commit client secret
- หลังอนุญาต scope ที่จำเป็น แอปโหลดข้อมูลรถจากชีตและไฟล์รูปจาก Drive
- เมื่อบันทึกข้อมูลฟอร์มหรือบันทึก ให้เขียนไปยัง Sheets API และแสดงสถานะกำลังบันทึก/สำเร็จ/ผิดพลาดอย่างเห็นได้ชัด
- ถ้าการเชื่อมต่อหรือบันทึกล้มเหลว ให้เก็บค่าที่ผู้ใช้กำลังแก้ไว้ในหน้าและแจ้งวิธีลองอีกครั้ง ห้ามแสดงสถานะสำเร็จหรือเขียนทับข้อมูลด้วยค่าเริ่มต้นเพราะการโหลดล้มเหลว
- ไม่ใช้ localStorage เป็นฐานข้อมูลหลัก อาจใช้เฉพาะข้อมูลชั่วคราวระหว่างการแก้ไขในเซสชัน
- มีปุ่มออกจากระบบ และไม่คง access token ในพื้นที่เก็บข้อมูลถาวร

## การเผยแพร่และความเป็นส่วนตัว

GitHub Pages ให้บริการเฉพาะไฟล์หน้าเว็บสาธารณะและค่ากำหนดที่ไม่ใช่ความลับ แอปต้องไม่ฝังข้อมูลรถหรือรูปไว้ใน source repository การอ่าน/เขียนชีตและไฟล์ต้องทำผ่าน OAuth ของผู้ใช้ที่ได้รับอนุญาตเท่านั้น คู่มือ deployment ระบุการเปิด Google Sheets API/Drive API, สร้าง OAuth Client ID สำหรับ origin ของ GitHub Pages, ตั้งค่า OAuth consent screen และกำหนด GitHub Pages

## เกณฑ์ยอมรับ

1. เปิดแอปแล้วเข้าสู่หน้าข้อมูลรถทันที และไม่มีเมนูหรือโค้ด UI ของห้าหมวดที่ถูกตัดออก
2. ผู้ใช้ที่ยังไม่ลงชื่อเข้าใช้เห็นการเชื่อมต่อ Google และไม่ได้เห็นข้อมูลรถ
3. ผู้ใช้ที่ได้รับสิทธิ์อ่านข้อมูลรถจากแท็บ `รถยนต์` และสามารถแก้ไข/บันทึกข้อมูลรถกลับไปยัง key เดิมโดยไม่เพิ่มข้อมูลรถซ้ำ
4. การอัปโหลดรูปและรูปใบขับขี่ใช้ได้ข้ามอุปกรณ์ โดยเก็บไฟล์ใน Drive และ file ID ในชีต
5. การโหลดหรือบันทึกล้มเหลวแสดงข้อผิดพลาดและคงค่าที่กำลังแก้ไว้
6. deployment instructions อธิบายค่าตั้งค่า Google APIs/OAuth และ GitHub Pages ครบถ้วน โดยไม่มี secret ใน Git
7. รีโปมี source แอปจริง (นำ HTML ปัจจุบันที่มีหน้ารถมาเป็นฐาน) ไม่ใช่มีเพียง README

## ข้อจำกัด/สมมติฐาน

- เครื่องมือในสภาพแวดล้อมนี้ไม่สามารถเปิดเนื้อหาสเปรดชีตที่แนบได้ในขณะเขียนสเปก จึงกำหนดให้ใช้ spreadsheet ID ที่ให้มาและเพิ่มแท็บ `รถยนต์` โดยรักษาแท็บเดิม หากผู้ใช้มีรูปแบบชีตที่ต้องการอยู่แล้ว ต้องตรวจสอบก่อนเริ่มทำ adapter ขั้นสุดท้าย
- การเปิด GitHub Pages และ OAuth ใน Google Cloud ต้องทำด้วยบัญชี/สิทธิ์ของเจ้าของรีโปและชีต; source จะมีคำแนะนำและค่าตัวอย่างที่จำเป็น แต่ไม่เก็บ credential ลับ
- ข้อมูลเดิมของรถอยู่ใน localStorage บนเครื่องและไม่ถูกส่งขึ้นชีตโดยอัตโนมัติ ต้องมีขั้นตอนนำเข้าครั้งแรกหรือกรอกใหม่
